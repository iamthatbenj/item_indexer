# Restore a portable archive (#19)

An approved founder opens **Check a portable archive**, selects **Review for restoration into a new private collection**, uploads a Family Belongings ZIP and checks the preview. **Confirm restore as current administrator** creates a new collection with that founder as its sole member and administrator. It cannot target an existing collection. Send fresh invitations only after reviewing the result. Preview-only mode retains no restoration result.

The review binds the exact ZIP SHA-256, upload ticket, expiry and founder account. Confirmation reads the same key into private temporary storage, compares the digest, then revalidates the graph and all required files. Private photo copies get attempt-scoped keys; removed-photo metadata gets no binary. Record IDs are remapped by type, and original contributor email labels remain credit-only, not sign-in addresses. Imports never consult or restore source membership. A re-export includes format 1.1 provenance and freshly scoped record IDs; see the [archive format](../../assets/portable-archive/FORMAT.md).

A single final database transaction rechecks the active session, founder approval and attempt lease, then publishes the collection, records, fresh membership and completion marker together. The result is deduplicated by founder and exact ZIP digest even after a reload: select the same ZIP again to reconcile an uncertain outcome. A separately generated archive is a different request. Expired review tickets require upload and review again. A single service-wide restore may run at once, with a 90-second fenced lease and a cooperative 45-second work deadline; the existing archive size and structural limits still apply. The maximum ZIP size is not a hosted throughput guarantee.

The review upload uses the existing one-day `staging/` lifecycle and expires for use after ten minutes. Private retained candidates under `photos/archive-restore/<attempt-id>/` are **not** subject to lifecycle expiry. Failed attempts fence off publication before deleting candidates best-effort; an interrupted put, unavailable database, delayed write or process termination can leave private objects. For operator reconciliation, pause restores, wait at least 24 hours, and compare attempt prefixes (`archive_restore_attempts`) with live `item_photos.photo_key`/`thumbnail_key` and current leases against a healthy primary database. Delete only confirmed unreferenced keys from expired attempts, never an active or uncertain candidate. Do not broaden the `staging/` lifecycle to retained photos.

## Local verification

All 25 archive browser/integration tests passed, including export → restore → re-export after removing access to the source and its photo objects, exact retained file checksums, preserved provenance and credit, duplicate confirmation, changed upload and approval rejection, and database publication failure followed by successful retry without old membership. Typecheck, production build, production dependency audit and nine hook regression tests passed. The staged review caught a contributor-limit issue: a restored collection with 200 credited contributors could not be re-exported. Format 1.1 now permits the live requester as a separate entry without dropping or merging historical credit. The expanded round-trip, offline verifier and rollback/retry tests passed after this fix. The full application suite and hosted acceptance have not been run for this change.

## Rollout

Apply additive migration `0012_archive_restoration.sql` **before** any approved push that auto-deploys. Confirm the existing private R2 staging rule and exact-origin PUT CORS; no new bucket or provider secret is required. Test a disposable hosted archive, confirm the credited history and images, reconcile a repeated confirmation, and verify historical members cannot open the restored collection without fresh invitations. Do not roll back to an older app after successful restores: it does not understand imported contributor labels or format 1.1 provenance. Prefer a fix-forward or temporarily disable new restoration without changing stored records or files.
