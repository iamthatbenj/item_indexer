# Portable archive preflight (#18)

An **approved founder** opens **Check a portable archive** from Family collections, selects a [Family Belongings format 1.0 or 1.1 ZIP](../../assets/portable-archive/FORMAT.md), and chooses **Upload and validate**. A supported preview shows the source label and counts of items, people, stories, retained photos, removed-photo records, revisions and retained files (main images plus thumbnails). Rejected content is distinct from an interrupted or failed check; retry requires an explicit upload. No collection, membership, account, restore grant or reusable staged result is created. The separate opt-in [restore workflow (#19)](archive-restore.md) keeps the private staged upload briefly and revalidates the exact reviewed ZIP after explicit confirmation.

## Private staging and bounds

- Exact-origin, bounded form POSTs use the current session and founder approval. A short-lived server-authenticated ticket binds a random storage key, account and exact byte count; no archive field authorizes any access. A fresh session/approval check gates the supported result. Upload and validation each have fixed 15-minute rate windows (4 per founder, 12 service-wide); these are not a provider spending cap.
- The browser sends ZIP bytes directly to private object storage through a ten-minute signed PUT restricted to the generated key, content length and content type. It does not send ZIP bytes through Vercel. No staged-object GET or listing grant is issued. Keep the source ZIP: results and selected files are not persisted by the app. As with other presigned PUTs, an issued URL can still be used until it expires; no founder/collection access can be gained from that URL.
- The server streams one ZIP of up to 256 MiB to a private temporary directory, then reads bounded ZIP members without extracting paths. Validation has a cooperative 45-second processing deadline and the validation route has a 60-second platform limit. ZIP work is capped at 1,004 entries and 272 MiB expanded bytes, with stricter per-file, domain-row and retained-photo limits. Only one bounded attachment is checked at a time. Malformed paths/entries, duplicate ZIP or JSON names, unsupported versions, inconsistent structure/history/attribution, incomplete/checksum-mismatched files and invalid JPEGs are rejected. Scripts and documentation inside the ZIP are never executed or rendered. Checksums show internal integrity, not a trusted source or authoritative family history.
- Preview-only validation attempts remove temporary disk files and the staged object best-effort, including rejections. Process termination, interruption before validation, failed cleanup and a late signed PUT can leave a private staged object. `staging/preflight/` is covered by the existing `staging/` one-day lifecycle; confirm this rule before rollout. Temporary function storage is not used as a durable handoff. Do not broaden expiration rules to retained photos.

## Verification and rollout

Run `npm test -- tests/archives.spec.ts`, `npm run typecheck`, `npm run build`, `npm audit --omit=dev`, and `git diff --check`. Tests use real #17 ZIPs and disposable database/storage fixtures; no private production archive is needed. The focused preflight/representative-archive run passed 6/6 tests after correcting two test-fixture errors (a nested locator and signing out without native form encoding). All 17 existing archive cases passed in the prior combined run. The 20-item, 21-photo real ZIP (6,103,263 bytes) uploaded and validated in about 1.9 seconds locally; the one-item preview took about 0.37 seconds. Typecheck, production build, production dependency audit (zero findings), nine hook regression tests and diff checks passed. The full application suite has not been rerun. Local measurements are not a claim about Vercel or R2 throughput, especially at the ZIP cap.

The original preview-only release needed no new migration, provider resource, secret, or lifecycle rule. For #19, follow the [restoration rollout prerequisites](archive-restore.md#rollout). Reuse the private bucket and exact-origin PUT CORS from [photo capture](photo-drafts.md). Do not push or deploy without approval. After an approved deployment, use a disposable hosted export to check the founder flow, preview counts, denial for an ordinary member, failure/retry on an interrupted upload, and actual mobile file picker behavior. Confirm appropriate production runtime budgets and observe provider usage before relying on larger archives. Rollback hides preflight; private abandoned bytes still expire under the existing staging rule. The accepted #17 export remains independent.
